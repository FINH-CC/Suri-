# SURI Kids Lab configurator — audit (2026-10-20)

Source: `index.html` at commit bcd402a (main). Measured locally and on https://suri-finhcc.vercel.app.

## What it is
A single 8.8 MB HTML file: ~430 lines of CSS, ~120 lines of markup, ~1,390 lines of Three.js r128 code, and one 8.6 MB `<script type="application/json">` holding the client's STEP geometry (handle, head, mount) as gzip+base64 arrays. Caps, grips, charms, themed mounts, bristles and stickers are generated procedurally at runtime. The 3D rendering itself (materials, lighting, SSAO, drawing mode) is good and worth keeping.

## Measurements
| What | Value |
|---|---|
| HTML over the wire (gzip) | 6.5 MB, every visit (the mesh data lives inside the HTML so it can never be cached separately) |
| CAD blob decoded | 6.5 MB of already-gzipped geometry: full STEP tessellation, no decimation, no Draco/meshopt |
| Time to interactive, desktop, local | ~7 s intro; real init is hidden behind a 7 s "bail" timer |
| Click → next paint | cap tile 20 ms, head tile 150 ms, cap swatch 150 ms, colourway 283 ms, **finish change 1,125 ms**, surprise 199 ms |
| Long tasks during 7 clicks | 14 long tasks, longest 451 ms |
| JS heap after a few clicks | 71 MB |

## Why it feels clunky and unreliable
1. **Thumbnails are rendered live with WebGL on the main thread.** Every option tile (7 parts × up to 6 options) is a fresh Three.js build + render + `toDataURL` PNG. Changing a colour or finish throws the cache away and re-renders every tile of every card. That is the 150 ms–1.1 s freezes.
2. **Procedural caps are expensive.** The cap is fitted to the head by scanning every head vertex (bristles included) in 72 × 26 slices, then smoothed and meshed with 96 × 84 rows, every time the head changes, plus once per cap thumbnail.
3. **No single source of truth for rendering.** State is mutated in place and each handler calls its own ad-hoc mix of `rebuild`, `rebuildStickers`, `renderPartSection`, `renderPresets`, `renderFinishes`, `persist` in different orders. A 400 ms polling loop in the frame function compares keys and rebuilds parts it thinks are stale. Thumbnail code temporarily swaps the global `state` and restores it in `finally`.
4. **Errors are swallowed.** Init failures are only `console.error`'d; the intro is force-dismissed after 7 s whatever happened, so a broken load just shows a blank stage. The last commit on main was a fix for exactly this.
5. **Flow logic is tangled.** Two modes with routes `[1,5]` and `[2,4,5]`, step 3 aliased to 2, step 4 shown inside 5 in pick mode, mode auto-switching when a review "Edit" jumps to a step. Markup for `.stage-title`, `.pills`, `.hint`, `.views`, `.tabs`, `.features` is either missing or hidden but still referenced in code.
6. **Mobile is close to unusable.** The 3D stage takes 62 svh and sets `touch-action:none`, so swiping on it rotates instead of scrolling. Once you scroll to the options the brush is completely off screen, so you pick parts blind. Two sticky bars (step dots + Next) take ~150 px. Sticker mode stays armed after placing, so stray taps keep adding stickers.
7. **No build, no modules, no types, no tests.** One file with one 8.6 MB line; Three.js r128 (2021) loaded from two different CDNs with the legacy `examples/js` globals.
8. **Smaller things.** Nav links all point at trysuri.com home. Checkout is a toast. Share links encode the full state in the URL hash (~550 chars). "My designs" stores a 300 px JPEG per design in localStorage. Fonts are trial files with a unicode-range workaround.

## Recommendation (slim version first)
Rebuild the shell, keep the 3D.
- Vite + TypeScript, ES modules, current Three.js from npm. Deploy as static files on Vercel (same project).
- Mesh data moved out of the HTML into one Draco/meshopt-compressed `.glb`, cached for a year; expect well under 1 MB. Progress bar on first load, instant afterwards.
- Option tiles become pre-rendered PNGs produced by a build script (one per part × option, neutral colour, CSS-tinted or a small colour set). No live thumbnail rendering in the page.
- One state store, one `render(state)` pass, no polling, no state swapping. Errors shown to the user with a retry.
- Cap fit computed once per head style at build time and shipped as data, not recomputed in the browser.
- One linear flow: Start (character or blank) → Design (parts + colours + stickers) → Name → Hand over. Review "Edit" links jump back without mode switching.
- Mobile: 3D viewer pinned at the top (~40% of the screen) while the options scroll underneath; page scroll works everywhere except a drag that starts on the brush; one bottom bar.
- Candidates to cut from v1: STL upload, My designs, Surprise me, drawing mode. Can come back once the base is solid.
