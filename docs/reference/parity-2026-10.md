## The tuning (fewest values, each with before/after)

| # | Where | Before | After | Why |
| --- | --- | --- | --- | --- |
| 1 | Key light intensity (`makeKeyLight` in `src/three/renderer.ts`, used by `scene.ts` and `snapshot.ts`) | `0.45` | `0.45 * Math.PI` (1.414) | r128 ran lights in legacy mode (irradiance x PI). Every part was ~10% darker (pip-front handle rgb(168,181,162) vs 185,200,179). |
| 2 | Key light colour (same place) | `0xfff8f0` (converted sRGB to linear) | `setRGB(1, 0xf8/255, 0xf0/255, LinearSRGBColorSpace)` | r128 used a hex light colour as-is, without the sRGB to linear step. |
| 3 | Stage framing box and contact shadow box (`frameDefault`, `placeContact` in `scene.ts`), passport hero camera (`frameHero` in `snapshot.ts`) | `Box3.expandByObject` | `expandByObjectR128` (`src/three/box.ts`) | r128 measured an `InstancedMesh` by its base geometry at the mesh origin, so the bristle tuft (a lathe at y≈0) stretched the box from y 0.90 down to -0.07. Current three uses the instance bounds. Without this the brush was framed ~3% larger and 20 px lower, and the contact shadow sat on the base instead of just under it. |

Not changed: `siliconeSheen` (sheen .32). After 1 and 2 the silicone cap and grip match legacy (pip-front grip
rgb(93,180,129) new vs rgb(90,179,127) legacy-settled; cap 93,179,128 vs 89,178,126), so the sheen energy
compensation did not need tuning. No `three@0.128.0` fallback needed.

Option and character tiles (`public/tiles`) were re-rendered with the corrected key light (`npm run tiles`); they read
slightly lighter, as legacy's live tiles did. Total 100 KB.

## Budgets

Production build (`npm run build`, served by `vite preview`), headed Chromium at 1280x900, measured with
`scripts/measure-budgets.ts`: click-to-paint is the time from the input event's `timeStamp` to the second
`requestAnimationFrame` after it; 5 runs each (3 for placing a sticker), median / max. Long Tasks from a
`PerformanceObserver` over the whole scripted flow (pick character, swap cap/head/grip, swatch, finish, place
stickers, name it).

8-17 ms; run-to-run spread between sessions was about ±10 ms.

### Fix made to get there

Before: with 3 stickers on the brush, any rebuild re-projected every sticker with `DecalGeometry` against the whole
CAD mesh (~80 ms per sticker on the handle): head tile 148 / 182 ms, handle colour 124 / 170 ms, grip tile
123 / 167 ms, placing a sticker 126 / 129 ms, Long Tasks up to 183 ms; with 5 or more stickers any rebuild would pass
200 ms. Now `decalProxy` (`src/three/stickers.ts`) hands `DecalGeometry` only the triangles that can reach the decal
box (a per-geometry centroid/radius cache, built once); the decal comes out identical (unit test
`tests/unit/decal-proxy.test.ts`). The numbers above are after the fix.

## Preview deploy

Preview (not production): https://suri-isof34ctt-finhcc.vercel.app (2026-10-21). Not behind Vercel login; the
Vercel toolbar is injected on previews. `/model`, `/tiles` and `/fonts` answer with
`Cache-Control: public, max-age=31536000, immutable`.

Smoke run on the preview, headed Chromium at 1440x900 and as an iPhone 13: load (intro gone in 3.9-4.8 s), Design
(cap tile, grip colour, Satin, one star sticker placed), Name it ("Smoke": box name and passport MRZ updated, box
render produced), Hand over (grown-up check, Check out toast "Concept prototype: checkout isn't connected yet."),
Share ("Link copied"; the link opened in a fresh browser shows the sticker and the name). No page errors; the only
console error is the browser's own `/favicon.ico` 404 (legacy has no favicon either). The first preview run found the
sticker hint swallowing the tap on phones (fixed, `pointer-events: none` on `.placing-hint`).
